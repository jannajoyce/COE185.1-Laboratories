1. (2 points) Suppose we relocated the three buttons from group B, bits 5-3 to
group D, bits 5-3, noting that the LED is still attached to group D, bit
2. Assuming appropriate DDRD values, consider the following method of turning
on the LED.

    PORTD = 0x04; // turn on the LED

Explain the problem with this approach and, in particular, what would stop
working after the execution of that line of code.


Hint: ignore the hardware propagation delays which are very small (tens of ns),
and think about how your program executes.


ANSWER:

When `PORTD = 0x04;` is executed, the entire PORTD register is set to the binary value `00000100`. This means:

- Bit 2 (PD2) is set to 1, turning on the LED.
- Bits 0, 1, 3, 4, 5, 6, and 7 are all set to 0.

This line, intended to turn on the LED connected to bit 2 of PORTD, creates a conflict with the button inputs connected to bits 5-3 of the same port. By setting `PORTD = 0x04`, bit 2 goes high (turning on the LED), but bits 5, 4, and 3 are cleared to 0, which effectively disables the button inputs.

Since the buttons rely on those bits being high or low to detect their state, clearing them to 0 prevents the program from reading their inputs correctly. As a result, even though the LED turns on as expected, the buttons become unresponsive. The program is no longer able to detect button presses, so it cannot respond to user inputs.
